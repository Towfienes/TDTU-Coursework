1. Linear Regression — Model & Theory
Problem: supervised regression. Given a feature vector with d numeric inputs, estimate a continuous target (e.g., house
price). For a dataset of m observations, the model predicts an affine function of the features.
1.1 Derivation of the mean squared error gradient
Define each residual ri = xiTw + b - yi. The cost is J = (1 / 2m) sum ri2. By the chain rule, the derivative of ri2 / 2 with
respect to wj is ri xij. The derivative with respect to b is ri because the intercept has coefficient one.
Therefore, dJ/dwj = (1/m) sum rixij, and dJ/db = (1/m) sum ri. Stacking all d derivatives gives the compact matrix
expression in the formula box.
1.2 Batch Gradient Descent algorithm
• Step 1. Initialize w as a zero vector, b = 0, choose learning rate eta = 0.08.
 
• Step 2. In each epoch, compute all predictions and the loss on training observations.
 
• Step 3. Compute gradient_w = XT(pred - y)/m and gradient_b = mean(pred - y).
 
• Step 4. Update w := w - eta * gradient_w; b := b - eta * gradient_b.
 
• Step 5. Repeat for 1200 epochs; never use the test set to update model parameters.
 
1.3 Implementation details
The LinearRegressionGD class in src/q1_models.py implements both the loss/gradient and update loop directly in
NumPy; no scikit-learn estimator is involved in fitting. The factor of 1/2 in the loss simplifies its derivative but does not
change the optimum.

3. Logistic Regression — Model & Theory
Problem: binary classification. The score z is transformed with the sigmoid function into the estimated probability
P(y=1|x). The default decision rule predicts positive class 1 when p is at least 0.5.
3.1 Why cross-entropy?
Squared error is suitable for continuous targets; for a Bernoulli outcome, the negative log-likelihood (binary
cross-entropy) is the appropriate objective. It heavily penalizes confident but incorrect predicted probabilities. We
implement it stably as mean(logaddexp(0, z) - y*z), avoiding log(0) and numerical overflow.
3.2 Gradient derivation: the chain rule
• For one observation, Ji = -yi log(pi) - (1-yi) log(1-pi).
 
• Differentiate with respect to p: dJi/dp = (pi-yi) / [pi(1-pi)].
 
• The sigmoid derivative is dp/dz = p(1-p), so these factors cancel: dJi/dz = pi - yi.
 
• Because dz/dwj = xij and dz/db = 1, the model gradients are XT(p-y)/m and mean(p-y).
 
3.3 Gradient Descent implementation
Initialize w = 0 and b = 0. At every epoch: form logits, apply a numerically stable sigmoid, calculate cross-entropy, derive
residuals (p-y), and update parameters by subtracting 0.13 times the gradients. Train for 2400 epochs. The class includes
a probability predictor and a configurable decision threshold.
Implementation: src/q1_models.py, class LogisticRegressionGD. The optimization algorithm is from scratch; scikit-learn
is used only for generating data, preprocessing, splitting, and measuring results.

6.1 Model training and selection protocol
• After cleaning, stratify a 70% development/30% held-out split. Keep test labels inaccessible for training or CV selection.
 
• For each model, run 5-fold StratifiedKFold cross-validation on the training partition only, with shuffling and seed 42.
 
• Inside each CV fold, fit median imputation and standard scaling using only that fold's training portion; then fit the
 estimator.
• Rank classifiers by training-fold mean macro-F1. Ties are resolved by a reproducible alphabetic secondary order.
 
• Refit models on the full development split; summarize accuracy, macro precision/recall/F1 and the gap between train
 and held-out test accuracy.
• The final champion is identified using CV, not by reading which model had the highest held-out test accuracy.
 
6.2 Evaluation metric definitions
Accuracy = correct / total predictions. Precision = TP/(TP+FP), Recall = TP/(TP+FN), and F1 is the harmonic mean of
precision and recall. Macro scores average the per-class scores equally, rather than weighting them by class frequency.
CV reports fold mean and standard deviation.
6.3 Methods compared
Dummy majority-class predictor; Logistic Regression; k-Nearest Neighbors; SVM (RBF and linear); Decision Tree;
Random Forest; Extra Trees; Gradient Boosting; AdaBoost; Gaussian Naive Bayes; Linear Discriminant Analysis;
Quadratic Discriminant Analysis (13 methods total). Hyperparameters are deterministic fixed baselines for a broad
comparison, not exhaustive model tuning.

8. Final Selection & Hold-Out Evaluation
By the prespecified CV criterion, the selected model is Gaussian Naive Bayes. Its held-out accuracy is 0.9111 and
macro-F1 is 0.9107. The held-out sample contains 45 observations.
 Figure 10. Confusion matrix for the CV-selected classifier; rows are actual classes, columns are predictions.
Why the highest test score is not automatically the selected model
A few candidates (e.g., LDA and QDA in this particular split) show higher measured test scores than the selected model.
Choosing a replacement based on those same test outcomes would turn the test set into a tuning signal. This report
therefore respects the prespecified training-only cross-validation criterion and uses the test split only as an independent
performance estimate.
Statistical caution
The sample size is modest; the test set contains only 45 records. A difference of one correctly classified flower changes
test accuracy by about 2.22 percentage points. Single-split rankings can therefore be unstable. A more comprehensive
study would repeat nested cross-validation and quantify uncertainty, using a larger independent test collection where
possible.
The experiment demonstrates standard classification workflows, not deployable flower-identification software.

9. Overfitting — Diagnosis & Mitigation
Overfitting happens when a model fits the development set so closely that its performance on new data is weaker. A
highly flexible Decision Tree can isolate individual training examples and achieve near-perfect in-sample performance,
even when the boundary is unnecessarily complex.
 Figure 11. Train-vs-cross-validation macro-F1 across maximum tree depths; the shaded area marks CV fold variation.
9.1 Observed generalization gap
The unrestricted tree achieves train macro-F1 = 1.0000 but hold-out macro-F1 = 0.9111, consistent with an overfitting
gap. Cross-validation scores plateau while training fit increases at greater depth.
9.2 Demonstration: early stopping via tree pre-pruning
Select max_depth from the candidates [1, 2, 3, 4, 5, 7, unrestricted] using mean 5-fold macro-F1 on training data only,
with simpler trees favored in a tie. The chosen depth is 3. The resulting train macro-F1 is 0.9807 and hold-out macro-F1
is 0.9327.

10. Overfitting Remedies by Algorithm & Conclusions
10.1 Model-specific prevention strategies
Method family
Practical overfitting controls
Logistic Regression / linear SVM
Increase regularization (reduce C), select relevant features, tune on CV
kNN
Increase k when k=1 is noisy, scale inputs, tune k inside CV
RBF SVM
Tune C and gamma using training folds; avoid unnecessarily complex boundaries
Decision Tree
Limit max_depth, min_samples_leaf, min_samples_split, use cost-complexity pruning
Random Forest / Extra Trees
Control maximum depth and leaf size; consider max_features and cross-validation
Boosting
Lower learning rate, fewer stages, shallower weak learners, early stopping
Naive Bayes / LDA / QDA
Inspect assumptions, regularize covariance estimates where appropriate
10.2 Synthesis of the two exam questions
Question 1 demonstrates analytic gradients, correct batch Gradient Descent implementation and finite-difference
verification. Regression predicts numeric targets with squared-error loss; binary Logistic Regression predicts
probabilities using cross-entropy. Their performance was measured on untouched held-out sets.
Question 2 demonstrates reproducible data analysis and leakage-safe classification. Thirteen algorithms were evaluated
under the same split and CV protocol. The Decision Tree complexity experiment shows why training performance alone
is not a sufficient quality measure. Pre-pruning a tree by a training-only CV selection rule improved the observed
held-out macro-F1 in this run.
10.3 Limitations and ethical considerations
• Both Q1 datasets are synthetic, so their success may not transfer to noisy real-world tasks.
 
• The Iris dataset is small and nearly separable; a 45-row held-out split yields high variability.
 
• The offline Iris copy was not fetched from OpenML live at execution; the corresponding OpenML ID is cited and the
 optional live-fetch path is supplied.
• Tree depth was tuned on training CV, but comparing many test scores in a report may invite post-hoc selection; use an
 independent final evaluation for deployment decisions.
• Data preprocessing and evaluated models should be tailored to data context; performance differences on Iris are not
 universal model rankings.
